# PE Fund Document Extraction Pipeline

Extracts structured data from private-equity fund documents (capital call notices, LP quarterly reports, cap tables),
checks it with arithmetic cross-validation, scores per-field confidence, routes uncertain documents to a human review
queue, and measures everything with a labelled evaluation harness.

> **Data is synthetic.** All documents are generated by `docextract/generator.py` from seeded random ground truth, so every
> document has exact labels. Fund and company names are fictional. Results show how the system behaves on these
> templates and failure modes, not on real client documents.

## Pipeline

```
PDF/scan
  -> parse      pdfplumber text; if no text layer, Tesseract OCR with per-line confidence
  -> classify   capital_call | lp_report | cap_table | unknown (unknown goes straight to review)
  -> extract    rules (regex baseline) | llm (OpenAI-compatible, e.g. Groq) | hybrid (LLM + rules agreement)
  -> validate   NAV roll-forward, line items sum to the call amount, holdings sum to totals,
                shares sum to total, pct = shares/total, date order, currency, ...
  -> score      passing arithmetic identity -> confidence raised to 0.95; failing check -> confidence x0.4
  -> route      all fields >= tau (0.85) and all checks pass -> auto-approve, else review queue (SQLite)
  -> review UI  Streamlit: source page next to editable fields, lowest confidence first; corrections are logged
```

The LLM never does arithmetic and never fills gaps: it only copies values stated in the document. Totals and
identities are checked in code, so a hallucinated or misread number is more likely to fail a check than to pass silently.

## Quick start

```bash
sudo apt install tesseract-ocr poppler-utils      # system deps
pip install -r requirements.txt
python -m docextract.cli generate --out data --n 10 --seed 7     # 90 labelled docs (3 tiers x 3 types x 10)
python -m docextract.cli eval --data data --extractor rules       # offline baseline, writes reports/
python -m unittest discover -s tests                              # 11 tests

# LLM / hybrid mode (any OpenAI-compatible endpoint)
export LLM_API_KEY=...            # LLM_BASE_URL (default Groq) and LLM_MODEL are optional
export PRICE_IN=0.59 PRICE_OUT=0.79   # USD per 1M tokens, for cost tracking
python -m docextract.cli eval --data data --extractor llm
python -m docextract.cli eval --data data --extractor hybrid

# Process real files and review them
python -m docextract.cli run path/to/pdfs --extractor hybrid --db docextract.db
streamlit run docextract/review_app.py
python -m docextract.cli export --db docextract.db     # approved documents as JSON
```

## Dataset tiers

| Tier | What it is |
|---|---|
| clean | Digital PDF, layout A (labelled lines, gridded tables, ISO dates) |
| complex | Digital PDF, layout B: different label wording, `5 March 2026` dates, `$` formats, un-gridded tables, **randomly swapped Cost/Fair Value columns**, extra columns, 10-16 row tables |
| noisy | Rasterised then rotated, blurred, noised and saved as image-only PDF (light/medium/heavy), so OCR is required |

## Results: regex baseline (the offline run, 90 docs, 2,588 labelled fields, tau = 0.85)

| Metric | Value |
|---|---|
| Field accuracy | 79.6% |
| Document exact match | 46.7% |
| Docs sent to human review | 52.2% |
| **Auto-approved document precision** | **97.7%** |
| **Auto-approved field precision** | **99.6%** (76.8% of fields auto-approved) |
| Silent errors (wrong but conf >= tau) | 7 of 2,588 |
| Latency P50 / P95 | 0.03s / 10.3s (P95 is Tesseract on scans) |

| Tier | Field acc. | Doc exact | Review rate | P95 |
|---|---|---|---|---|
| clean | 100.0% | 100.0% | 0.0% | 0.02s |
| complex | 91.6% | 33.3% | 66.7% | 0.05s |
| noisy | 44.3% | 6.7% | 90.0% | 10.5s |

Full tables (threshold sweep, worst fields, silent errors): `reports/eval_rules.md`.

**LLM and hybrid numbers are not in this repo yet.** The sandbox this was built in had no network, so only the
transport-stubbed unit tests exercise the LLM path. Run the two `eval` commands above with your key and add the results.
Expected pattern: the LLM should fix the "complex" label-variant failures; the hybrid should cut silent errors further.

## Failure analysis (from the baseline run)

1. **Swapped table columns passed every check (239 silent errors in v0).** Positional parsing read `Fair Value` as
   `Cost` and the totals row was read the same way, so sums matched and the arithmetic checks passed. Fix: read the header
   to decide column order. Silent errors fell to 21.
2. **The separator regex swallowed minus signs**, turning an IRR of -1.3% into +1.3% at 0.92 confidence. The silent-error
   table exposed it. Fix: only `:` is a separator.
3. **OCR damage on values no identity covers** (`Ventures |`, `165,000.00` read as `165,000.90`). Added format heuristics
   (stray glyphs in names, malformed numbers) that cut confidence. Silent errors fell 21 -> 7.
4. **Unknown label wording (layout B)** makes the baseline return nothing for 3 capital-call fields. These are caught
   by the missing-field rule (routed to review), but the cure is the LLM extractor, not more regexes.
5. **Scanned tables with grid lines.** OCR drops or garbles many rows (noisy tier 44% field accuracy). Contrast
   thresholding and median filtering made recall worse in my test, so I left the pipeline as is. The right fix is a
   vision-LLM fallback for low-confidence OCR pages; the hooks are `parsing._ocr` and the `llm` extractor.

Two changes between the "v0" and final numbers are mixed together: the extractor fixes above, and a fairer evaluation that
aligns table rows by name rather than index (so one dropped OCR row no longer marks every later row wrong). The v0 report is
kept in `reports/eval_rules_v0_index-aligned.md`.

## Known limits

- Synthetic data, one currency per document, 2026 dates only, no multi-page layout variation beyond what is generated.
- Schemas use dataclasses plus hand-written validators, not Pydantic (Pydantic could not be installed in the build sandbox).
  Moving `schemas.py` and `validators.py` to Pydantic models is a mechanical change if you want it.
- The Streamlit review UI is syntax-checked but was not launched in the build sandbox.
- Confidence is heuristic (rule hit x OCR confidence, adjusted by checks), not a calibrated probability.
